# Design: retiring the second engine

## D1. What is actually being given up

Not the corpus. `fixtures/recordings` is 51 committed files at the repository root, read by
`RecordingParityTest`, `CorpusReplayTest`, `ValidatorImpersonationTest`, `DealParityTest`,
`ViewRedactionTest`, `CorpusCoverageTest` and a generated constant in
`shared/shapes/build.gradle.kts`. None of that reads `legacy-web/`. Deleting the workspace
leaves every one of those gates running exactly as it does today.

What is given up is the ability to **regenerate** it. `legacy-web/tools/generate-recordings.ts`
produced those 50 games from the TypeScript engine, and `replay-fixtures.test.ts` proved that
engine still replayed them. After the deletion the corpus is a frozen artefact: still a real
gate against the Kotlin engine drifting, no longer evidence that two implementations agree
today, and not extensible.

Being precise about that matters, because the parity language throughout `docs/` was written
when both halves were live and should be read with this in mind. README §1d already says so.

## D2. The decision: freeze the corpus, do not port the generator

The obvious move is to port `generate-recordings.ts` to Kotlin before deleting the TypeScript
one, so the corpus stays extensible. **Rejected**, and this is the decision this change exists
to record.

A recording generated by the engine under test proves that the engine agrees with itself. It
catches a *change* — which is worth having, and is exactly what `RecordingRoundTripTest` (§6l)
and the tournament baseline (§6k) already do, on all three targets and against committed
numbers. It cannot catch what the corpus was built to catch: a handler that was ported wrong
from the start, in a way that is self-consistent. Only an implementation written from the rules
rather than from the Kotlin can do that, and after this change there is no such implementation.

So the fifty recordings are worth more as a **fossil** than as a seed corpus. They are the last
artefact in the repository produced by an engine that had never seen this one, and regenerating
them — even once, even to add a scenario — destroys that property permanently and silently,
because the file format does not record which engine wrote it.

Three consequences follow, and they are tasks rather than intentions:

1. `fixtures/recordings/README.md` says the directory is frozen, why, and what to do instead.
2. New Kotlin-generated recordings go in a **different directory** with its own README, so the
   two can never be confused by a future reader or a future script.
3. `docs/game-engine/RECORDING.md` stops describing a cross-language contract in the present
   tense.

## D3. Leave the provenance comments

Roughly 79 Kotlin files carry a comment of the form *"Ported from
`legacy-web/packages/engine/src/lib/…`"*. The instinct is to delete them along with the
directory.

**Leave them.** They answer a question a reader will still have — *why is this written this
way?* — and the answer is genuinely "because it is a faithful port, and the parity gate is what
holds it still" (README §6b explains why the handlers mutate, which makes no sense without it).
A path into a deleted directory is still a precise citation: the history has it, and the
alternative is a port with no stated source.

The one thing to fix is any comment that tells somebody to **run** something in `legacy-web/`,
which is an instruction rather than a citation. Those are in `.claude/commands/` and in the
project documents, not in the Kotlin.

## D4. What replaces the second engine as a check

Nothing replaces it exactly, and pretending otherwise is how a gate quietly becomes a
formality. What exists instead, and what each actually proves:

| Gate | Proves | Does not prove |
| --- | --- | --- |
| The 50-recording corpus replay | the Kotlin engine still computes what TypeScript computed in 2026 | that either was right |
| `RecordingRoundTripTest` (§6l) | a whole game generated on a target replays through its own JSON on that target | anything about a second implementation |
| The self-play tournament (§6k) | the bot's aggregate play has not changed by accident | that it is good |
| `SelfPlayGateTest` | every action four bots propose is legal, and games finish | that the rules are the right rules |
| `ScenariosTest`, `VintoRulesTest` and the rest of `commonTest` | the engine matches the rules **as written down** | that the rules document is right |

The last row is the one that carries the most weight after this change, and it is the argument
for `docs/game-engine/VINTO_RULES.md` and `SCENARIOS.md` being maintained as carefully as the
code — they become the only independent statement of the game left in the repository.

## D5. Ordering

The deletion is last, and reversible until it happens. Everything before it is documentation
and policy, so if the freeze decision is ever revisited, it is revisited with `legacy-web/`
still present rather than out of `git log`.
